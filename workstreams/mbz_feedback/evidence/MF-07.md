## Proposed decisions

### P1: `tasks.tracking_file_warnings` imports `hook.WRITERS` inside the function

`hook` imports `registry` and `handoff`, which import `tasks`, so a top-level import is a cycle. `audit.py` and `cli.py` already import inside a function, with a comment saying why. Rejected: moving the names to a lower module, which needs `project.py` and `baseline.py`, off this task's file list, and which still can't take `handoff.FILE_NAME` without its own cycle.

### P2: `ws update --acceptance` warns about every item of the task, not only the corrected one

The warning has one source and each line gives its item number, so a line about another item is still true. Rejected: filtering to the corrected number, more code to hide a true warning.

### P3: A name counts only whole, and an optional `n` labels a task with no id

`MY_DECISIONS.md`, `old-PROGRESS.md` and `DECISIONS.md.bak` don't warn, and a test pins that. An item's `expect` counts as well as its text, since `acceptance_text` includes it. `tracking_file_warnings(task, n=0)` adds `n` to D-TRACKING's signature so `validate_tasks` labels an id-less task as its other rules do. Rejected: a plain substring check, which warns on other files.
