## Acceptance

1. the diff parser's line numbers and kinds have tests -> ui/web/tests/logic.test.mjs: `a diff keeps its line numbers on each side`, `a removed or added line that looks like a header stays a line`, `a diff with no hunks is only its header`. Run by `PageLogicTests`.
2. the review screen fetches only through /api/review and /api/queue, and a test holds that -> tests/test_web.py `ReviewScreensTests`: review.js's only fetch is `urls.review`, queue.js has none of its own, and the shell fetches the queue. `checks` gained `title` and `status` so the screen needs no snapshot.

Seen in the browser on the sample project: a branch task with a failing evidence gate, "Nothing quoted." beside its second item, `j`, `k`, `n`, `p` and `s`, and a landed task. Repo markup in the title and proof drew as text.

## Proposed decisions

### P1: the review screen shows the gates and proofs beside the diff, not in place of it
The pane swaps evidence for diff because one tree draws 100,000 characters. A browser needn't, and judging a claim against code is the job. Rejected: tabs, which is how a reader loses their place.

### P2: a button copies `ws settle`, and the page never lands anything
Landing is `ws settle`, which merges and may run a project's commands. Rejected: a Land button, which would need a new write path around `ws act`.

## Gotchas and follow-ups

The evidence file itself is in the diffstat, as it's part of what the branch changed. It's listed last only because of its path.
