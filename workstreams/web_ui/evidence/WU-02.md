## Proposed decisions

### P1: a per-launch token as well as Host and Origin checks
Host and Origin stop a web page. They don't stop another account on the same machine, which can reach the port and would be able to read a private repo's diffs and commit as this user. The token costs one query parameter. Rejected: Host and Origin alone, which is what a dev server usually does, but a dev server doesn't commit.

### P2: the cookie is SameSite=Lax
Strict isn't sent on the redirect after a link followed from another app's page, which shows a confusing 401 on first open. Lax still holds it back from cross-site POSTs and frames, and the Origin check stops the write anyway. Rejected: Strict.

### P3: a stable port per project, chosen from the root's hash
A browser's own storage is per origin, so a fresh port each launch would lose the review queue's "seen" marks. If the port's taken, any free one is used. Rejected: a fixed port, as two projects can be served at once.

## Gotchas and follow-ups

`frame-ancestors 'none'` will need loosening, on an explicit flag, for M9's webview. A cross-site frame also wouldn't get the Lax cookie, so M9 will need its own answer there.
