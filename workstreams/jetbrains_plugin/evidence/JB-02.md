## Proposed decisions

### P1: the headless tests disable the IDE's `com.intellij.modules.ultimate` plugin
Against IntelliJ IDEA 2026.2.4 (the unified distribution), every `BasePlatformTestCase` failed with `Cannot create extension (class=Q.Q.Q.Q.V) [Plugin: com.intellij.modules.ultimate]`. That plugin's only extension is a `postStartupActivity` with no constructor a light test project can supply. `tasks.prepareTestSandbox { disabledPlugins.add("com.intellij.modules.ultimate") }` disables it in the test sandbox only. The plugin uses nothing from it, and `verifyPlugin` still checks against the full IDEs. Rejected: IntelliJ IDEA Community, which is no longer published for 2026.2 (`Could not find idea:ideaIC:2026.2.4`). Also rejected: compiling against the local Android Studio, which plan T1 rules out.

### P2: the startup activity does nothing in unit-test mode, and tests call `Workstreams.open` themselves
A light test project's base dir is a temp folder that isn't a workstream project. If the startup activity ran there, it would fire the not-a-project notification before each test, and the "one notification" checks couldn't hold. So `OpenWorkstreams` returns early when `isUnitTestMode`, and the tests open the sample folder through the project service. Rejected: opening a second heavy project per test with `PlatformTestUtil.loadAndOpenProject`, which is slower and still races the activity.

### P3: the Gradle `test` task declares the checkout's `src/workstream` as an input
Otherwise Gradle reuses the last test result after a CLI change. My first `ws verify` recorded `make test-jetbrains 1.2s` because of that. Rejected: `--rerun` in the make target, which reruns the tests even when nothing changed.

### P4: settings take an argv split the way a run configuration's arguments are
The `ws command` and `Agent command` fields go through `ParametersListUtil.parse`/`join`, and are stored as string lists that default to `["ws"]` and `[]`. Rejected: a JSON array in a text field, which is harder to type and gives nothing more.

### P5: the platform is IntelliJ IDEA 2026.2.4 (262.11879.100), with Kotlin 2.3.20 and Gradle 9.7.1
2026.2.4 is the latest 262 release in JetBrains' repository. Kotlin 2.3.20 and the 9.7.1 wrapper were already cached. I generated the wrapper with `--no-validate-url`, because services.gradle.org returned 504 at the time. `validateDistributionUrl` is back to `true` in the properties. Escaping uses `HtmlChunk.text`, the platform's escaper, where plan T2 names `XmlStringUtil.escapeString`. Both escape `<`, `>`, `&` and quotes. Rejected: the 2026.2 base release, which is older within the same branch and gives nothing more.
