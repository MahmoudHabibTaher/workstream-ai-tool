## Proposed decisions

### D009: the refresh test stands in for the native file watcher, which the platform disables in unit-test mode

`NativeFileWatcherImpl.isDisabled()` returns true whenever `isUnitTestMode` is true, so no headless test can see fsnotifier deliver a change. The test checks the watch requests `addRootsToWatch`/`replaceWatchedRoots` registered, then makes the outside commit and refreshes the VFS the way the watcher's report would. Everything after the refresh is the real code path: `VFS_CHANGES`, the refresh-path filter, the 300 ms debounce and the reload. To make change events fire at all, `Workstreams.watch` loads each refresh path into the VFS, walking recursive ones, since the VFS reports changes only for files it already knows. JB-07 should confirm by hand that a shell commit reloads the tree in a running IDE. Rejected: a heavy test with a real watcher, which the platform won't start in test mode.

### D010: the 300 ms debounce is a coroutine `Flow.debounce` on the service's scope, not `MergingUpdateQueue` or `Alarm`

Pokes go into a `MutableSharedFlow` with a one-slot buffer that drops the oldest poke, read through `debounce(300)` and collected sequentially. A poke during a reload therefore makes exactly one more reload, as the VS Code `debounce.ts` does, and the reload runs on `Dispatchers.IO`, off the EDT. Plan T5 names `MergingUpdateQueue` or `Alarm`. `MergingUpdateQueue` runs on the EDT by default and passes straight through in unit-test mode, which would hide the once-per-burst behaviour from the test. Rejected: `MergingUpdateQueue` with pass-through turned off and a pooled thread.

### D011: gateSummary and rangeLine are left for JB-05

D-VIEWS lists `gateSummary` and `rangeLine` among `logic/`'s ports. This task's acceptance names only waveLine, badgesOf, lanes and splitRows, and JB-05's first acceptance item is "JUnit tests for gateSummary and rangeLine pass with ui/vscode's cases". So `logic/Format.kt` ports waveLine, ageOf, badgesOf, blockedLine, lanes, splitRows and errorCount. JB-05 adds the other two, along with statLine. Rejected: porting them here with no review tab to use them.

### D012: Kotlin compiles with `jvmDefault = NO_COMPATIBILITY`

Without it, Kotlin 2.3 emits bridges for every interface default the plugin doesn't override, such as `ToolWindowFactory.isApplicable`, `isDoNotActivateOnStart`, `manage` and `getIcon`, and `StatusBarWidget.getPresentation(PlatformType)`. The verifier then counted 6 to 7 deprecated and 6 experimental API usages that the plugin never makes. With the setting, both IDEs report plain `Compatible`. The document opener also uses `OpenFileDescriptor.navigate` rather than `FileEditorManager.openFile(VirtualFile, boolean)`, which 263 deprecates. Rejected: leaving the bridges and the verifier noise.

### D013: the sink scan in test_jetbrains_files.py reads only `src/main`

The new tests' expected strings hold `<html>` on purpose, for example the escaped tooltip they assert. Those strings aren't sinks, and they would fail a scan of the test sources. The scan therefore covers the shipped code only, and it gained three sink patterns: `getTooltipText()`, `.tooltip =` and `setTooltip(`. Rejected: rewriting each expected string so that no line holds `<html>`.
