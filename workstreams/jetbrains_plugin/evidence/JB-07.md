## Proposed decisions

### P1: the one deprecated call on 263 is recorded, not fixed, in JB-07

`make verify-jetbrains` reports `Compatible. 1 usage of deprecated API` on IU-263, from `ReviewOpen.openEvidence`. Acceptance 1 asks for "compatible", which it is. The fix is in `ReviewOpen.kt`, outside JB-07's files, so it is a follow-up and is listed under Left open in 0018 and Known issues in the guide. Rejected: editing `ReviewOpen.kt` here.

### P2: the zip was installed from a copy in `dist/jetbrains/`, also served by a local plugin repository

At the owner's request the zip was copied to the gitignored `dist/jetbrains/`, beside an `updatePlugins.xml` that names it, so the IDEs can add `file:///.../dist/jetbrains/updatePlugins.xml` as a custom repository. Nothing committed builds it yet. Rejected: installing straight from `ui/jetbrains/build/distributions`, which is buried in a worktree. **Open.**

### P3: the stale-write check was proven with the box open across a registry change

An empty commit doesn't change the registry or queue hashes, so it can't make a view stale, and a write from a view that has reloaded is rightly allowed. The proof is the VS-08 recipe: box open, registry changed from a shell, then OK. Rejected: counting the empty-commit tries.

### P4: Android Studio was checked with the other `Workstreams` plugin disabled

Android Studio 2026.2 here has another workstream plugin 1.1.0, which registers a tool window with id `Workstreams`, the same as this plugin's. The owner chose to disable it for the check. How the two coexist is untested. Rejected: installing alongside it, or blocking JB-07 on renaming the id. **Open.**

## Gotchas and follow-ups

- The tool window id `Workstreams` is generic and clashes with another plugin's (P4). A unique id such as `dev.workstream.jetbrains` would avoid it.
- `ReviewOpen.openEvidence` uses the deprecated `FileEditorManager.openFile` (P1); `OpenFileDescriptor.navigate`, as Documents use, would clear it.
- A `make` target that refreshes `dist/jetbrains/` and its `updatePlugins.xml` would make the local repository repeatable (P2). The version must rise for the IDE to offer an update.
- The sample's `.idea/` is untracked after IntelliJ opened it; harmless for a throwaway sample.
