## Proposed decisions

### P1: the Terminal tab runs the agent through the person's login, interactive shell

Recorded as D037 by the owner; the shape is this task's. `TerminalTarget`'s opener sets `myShellCommand = shellArgv(System.getenv("SHELL"), argv)`, which for sh, bash, zsh, ksh and dash at an absolute path gives `[$SHELL, -l, -i, -c, 'exec "$@"', ws-launch, ...argv]`. Any other shell, or none, runs the argv as it is. From a bare `PATH=/usr/bin:/bin`, the wrap found `claude` 2.1.316 and passed `a "quoted" $HOME prompt` through unchanged. The dialog and `Started.argv` keep the plain argv. Rejected: reading the IDE's loaded shell environment (it had no `~/.zshrc` PATH here), and resolving the agent's absolute path in the plugin, which would miss version managers and aliases.

### P2: the checks are a list of rows, blocking first, and the dialog's error line names what blocks

`LaunchDialog` lists the checks in a `JBList` drawn through `ColoredListCellRenderer`, with `AllIcons.General.Error`, `Warning` or `InspectionsOK`. `Launches.ordered` puts failed blocking checks first, then warnings, then passed checks. `setErrorText(Text.html("Blocked by validate, wave, claim: fix these checks to launch."))` shows the reason by the buttons. A check run that failed outright is one blocking row. Rejected: keeping the text area and only scrolling it to the top, which would still give no reason next to OK.
