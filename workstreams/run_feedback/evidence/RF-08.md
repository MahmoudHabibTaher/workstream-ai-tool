## Proposed decisions

### D010: `ws wave` and the lanes screen use the handoff's reason chain

A blocked task shows `blockedReason`, then `notes`, then its title, as D007 does for the handoff, so older queues' reasons still appear. Rejected: reason only, which would show nothing for a hand-blocked task.

### D011: `heldBack` has one entry per task, holder and path

A task held by two tasks, or on two paths, gets one entry each, so every cause is visible and each must clear. The schema's `{id, by, path}` shape can't hold more than one cause per entry. Rejected: first cause only, which hides what else must land.

### D012: the claim test and lanes test sit outside the listed test files

The `ws claim --commit` test is in `tests/test_protocol.py`, beside the other batch refusals and their git setup. The lanes test is in `ui/web/tests/logic.test.mjs`, the only place JS runs, which needed `waveNotes` exported from `lanes.js`. Rejected: calling `batch_problems` directly from `tests/test_tasks.py`, which wouldn't prove the command refuses.

## Gotchas and follow-ups

- `ws next` still uses `graph.actionable` alone (`src/workstream/cli.py`, `cmd_next`), so it can name a held-back task, which `ws claim --commit` then refuses. Not in D-WAVE, so left alone.
- Plain `ws claim` without `--commit` skips `batch_problems`, as it already did, so it doesn't refuse the overlap.
- D-WAVE's rule is applied literally: a task hand-marked blocked that also has `blockedBy` on a todo task sharing its file holds that todo task back, and neither can move until someone acts. The wave reports it as stuck or held back, so it is visible. `validate` doesn't warn about that pair, because it skips overlaps along a `blockedBy` chain.
- Validate's overlap warning now fires for cross-phase overlaps between open tasks, so existing queues may show more warnings. That is the decision's intent, and they stay warnings.
- `ui/mod` (the Claude Code pane) doesn't show heldBack. Its types name only what it reads, and it wasn't in this task's list.
