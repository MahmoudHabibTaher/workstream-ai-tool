## Proposed decisions

### P1: `ws init` no longer writes a config when it refuses
The dirty-tree check runs before anything is created, so a refused init leaves no half-set-up repo behind. Rejected: writing the registry first, which is what a run needs, and cleaning it up on refusal.

### P2: when every candidate fails, the comment shows one that actually ran
A failure says more than a tool not being installed. Rejected: always showing the first candidate, which would hide an npm failure behind a missing pnpm.

## Gotchas and follow-ups

A command that changes tracked files at init leaves those changes in the tree: `ws init` reports it and doesn't undo them, because undoing could lose something. It says to review what's left.
