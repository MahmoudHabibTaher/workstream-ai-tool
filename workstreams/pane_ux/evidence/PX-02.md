## Proposed decisions

### P1: a task under two parents is drawn in full once, then as a "(shown above)" repeat
The Graph is a depth-first walk from the tasks that wait on nothing here, with children taken from `unblocks` in priority order. A task with two blockers appears under both, so each edge shows, but it recurses only the first time. Leftovers (a cycle) are drawn at the top level so no task is dropped. Rejected: drawing each task once under its first parent only, which hides the second edge.

### P2: a Graph line jumps to Tasks with that task expanded
Until PX-03 adds the task page, there is nowhere else to show a task. PX-03 can point `onJump` at the task page instead. Rejected: making Graph lines inert.

### P3: Overview's documents are buttons that open the feed tab
The four documents the feed already pages (plan, progress, decisions, handoff) are shown when the snapshot gives a path, and pressing one opens that feed tab. Back from the feed returns to Overview, because `sub` is kept in the view. Evidence files are not listed: the feed has no tab for them. Rejected: listing bare paths.

### P4: Overview's verify commands are each task's commands, once per label
The snapshot has no workstream-level command list, so Overview shows the union of the tasks' `verifyCommands`, in the order tasks first name them. Rejected: reading the project config, which would mean the pane computing a fact the CLI doesn't give.
