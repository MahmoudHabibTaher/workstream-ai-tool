## Proposed decisions

### P1: the rule-map row is a new `project` row, not an updated one
`docs/rule-map.md` had no row for the edit-tool rule, so there was nothing to repoint. I added `| new | On Claude Code, a background worker uses its edit tools ... | project | An agent fact, in the claude-code adapter's `[worker] rules`, ... |`, beside the other worker rows. `project` is the kind the map defines for an agent fact kept in an adapter. Rejected: a `code` row naming `brief._adapter_rule_lines`, since the text lives in the TOML, not the code.

### P2: this repo's `.claude/agents/ws-worker.md` is regenerated by text to apply, not by `ws adapt` here
The brief marks `.claude/` as not editable from the background, so I didn't run `ws adapt claude-code` in the worktree. The exact text it would write is below. It equals `adapt.worker_text(adapt.load('claude-code'))` on this branch (diffed against the current file: only the two new lines at the end). Someone in the foreground should run `ws adapt claude-code --force` on the integration checkout after merge (or apply the text), so `.workstream/adapters.json` records the new file. This differs from the plan's "Run `ws adapt claude-code` here". Rejected: running `ws adapt claude-code` from the background, which the brief says not to try for `.claude/`.
