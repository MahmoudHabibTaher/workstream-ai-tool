## Proposed decisions

### P1: a workstream's tasks file is the first path its own snapshot's `watch` lists that the root snapshot's doesn't

`ws snapshot -w <id>` has no `paths.tasks`. Its `watch` comes from `watch_paths`, which lists the registry, then the queue, then the handoff and progress. `tasksFileOf` takes the first entry the root's `watch` lacks, so the path still comes from the CLI. That leans on the order `watch_paths` uses. A `paths.tasks` in the snapshot would be cleaner, but `src/workstream/snapshot.py` is outside this task's files. Rejected: joining `repoRoot`, the row's `path` and `tasks_list.json` in the extension, which would hard-code a file name the CLI owns. **Open.**

### P2: Budget runs when it first comes into sight and on Refresh, not on the store's file-change reloads

`ws audit context` measures the tool's own context, and nothing under the workstreams changes it, so a reload on every claim would rerun it for nothing. A Refresh while the view is hidden only drops the rows, and they're read when the view is next shown. Rejected: rerunning on every store change while visible.

### P3: findings' writes show in the Health tree's context menu too

The write menus' `when` is now `view =~ /^workstreams\.(registry|health)$/`, keyed on the same `act:<write>` contextValue words. `test_writes_and_launches_show_only_where_offered` was updated to match. Launches stay Registry-only. Rejected: quick fixes only, which leaves a finding with no workstream (none offer a write today) or an unopened tasks file unreachable from the tree.

### P4: the Health tree leaves out the web UI's "Progress out of date" rows

`health.js` also lists rows with `progressStale` and a Sync button. The Registry tree already offers Sync on those rows through the row's `actions`, and acceptance covers findings. Rejected: copying that section now.
