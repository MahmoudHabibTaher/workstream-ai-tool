## Proposed decisions

### D009: `--show` is left out of cli.ts until VS-06
D-CLI lists `--show` among `loadReview`'s options. VS-02 adds `--show` and isn't on this branch, so an argv using it would fail acceptance 4's real-CLI check here. VS-06 depends on VS-02, so it should add `loadShow` along with its line in `test_every_argv_cli_ts_builds`. Rejected: building the argv now and skipping its check when the CLI lacks the flag, which would hide a real mismatch. **Open.**

### D010: `@types/node` is a fifth dev dependency, pinned to Node 20
`cli.ts` uses `node:child_process`, and `tsc` can't type it without node types. D001 lists four dev dependencies. I pinned `@types/node@^20`, the Node that the `^1.100.0` engine floor ships with, as T10 does for `@types/vscode`. It is dev-only, so the extension still has no runtime dependencies. Rejected: declaring the module types by hand. **Open.**

### D011: TypeScript 7.0.2 emits CommonJS
`npm install` resolved `typescript@^7.0.2`, and it accepts all three T9 options. `module: nodenext` with no `"type"` in package.json emits CommonJS, the module format every VS Code from 1.100 loads. Node then reparses the `.ts` tests as ESM, so the test command adds `--disable-warning=MODULE_TYPELESS_PACKAGE_JSON`. Rejected: `"type": "module"`, which would need ESM extension support at the engine floor.

### D012: the startup logic is `src/logic/start.ts`, and activate returns a small test API
`start(cli, folders)` resolves roots, then loads snapshots, and returns the one message to show. `activate` returns `{ready, ran, shown}` so the integration test can see every argv run and every message shown. VS-04 can add the views behind the same state. `resolveRoots` skips folders that aren't projects and reports a problem only when none is one. Rejected: stubbing `window.showErrorMessage` inside the extension host.
