## Proposed decisions

### P1: a branch task's evidence opens read-only from `--checks`; a landed task's opens as the file
The integration checkout has no evidence file yet for work still on a branch (`review` gives `evidence: null`), so a branch's evidence opens as a `ws-review:` document. It serves `checks.evidenceText`, which is the same text the gates judged: the branch's copy first, then main's. A landed task's opens as the real file at the `evidence` path. Rejected: always opening the on-disk path, which is missing or stale for branch work. Also rejected: `--show` on the evidence path, which needs the workstream folder's relative path and isn't there when the evidence isn't in the diffstat.

### P2: D009 is settled by this task
`loadShow` builds `['review', task, '-w', wsId, '--show', path, '--side', side]`. That line is in `test_every_argv_cli_ts_builds`, and the real CLI accepts it for both sides. D009 can close. Rejected: keeping `--show` out of cli.ts and calling it from the view, which would put a second process call outside cli.ts.

### P3: a file loads both sides before the diff opens, and each `ws-review:` URI names its revision
The extension needs both sides first to tell whether either is binary, which opens nothing. It hands the texts to the content provider and opens `vscode.diff` on URIs whose query carries root, workstream, task, side and the rev `--show` returned. A cached text therefore never stands for a later revision. Rejected: letting the provider fetch lazily, which can't stop a binary diff from opening.

### P4: activate's test API grew `review` and `opened`
On top of D021: `review` is the Review tree, and `opened` records what each file or evidence click opened (`diff`, `binary`, `failed` or `evidence`). Rejected: reading only the tab groups, which can't show that a binary click opened nothing on purpose.

### P5: the Review tree groups by `state`, even though the CLI already sorts that way
`queueNodes` splits the queue into **On a branch** and **Landed**, keeping the CLI's order inside each. It leaves out an empty group and says "Nothing to review." when the queue is empty. This is a display arrangement: the order within each group is still the CLI's. Rejected: a flat list, which doesn't show where branch work ends.

## Gotchas and follow-ups

- The Review tree reloads with the store, which watches the snapshot's `refresh` paths. A commit made on a task branch inside its worktree may not touch any of those paths, so the queue's diffstat for that task can stay stale until Refresh. Refresh is on the Review view's title bar too.
- The ws-review skill and README.md still don't mention `--show` (carried over from VS-02). Both are outside this task's files.
